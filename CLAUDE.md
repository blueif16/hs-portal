## Architecture (where things live)

- `extension/` — the loadable extension (zero-build, Load unpacked).
  - `src/lib/{human,plan,governor,planner}.js` — shared modules; attach to `globalThis.__hs.*` (loaded in bg via `importScripts`, in content via `content_scripts`).
  - `src/content/engine.js` — atomic XHS ops; selectors in the `SEL` map. Also: `fetchMe`/`fetchSelfInfo` (own-account API reads) + a window-message bridge that relays nethook findings to bg.
  - `src/content/nethook.js` — **MAIN-world** net interceptor (reads the page's OWN signed XHS API responses; `postMessage`→engine.js→bg). The blessed way to read response bodies (MV3 webRequest can't — see ARCHITECTURE.md §injected page hook).
  - `src/background.js` — orchestrator owns the loop, governor, config + Plan store + **account-traction store (`hs_account`)**, AI handler. **No cloud.**
  - `popup/` — toolbar launcher (status glance + Content Studio button); the real 养号 dashboard is the in-page panel.
  - `src/content/panel.js` — the in-page Shadow-DOM 养号 dashboard (home plan-picker + run, account-traction tile, editor, log).
  - `src/content/publisher.js` — creator-page publish driver (msg type `hs:pub`; co-injects on `creator.xiaohongshu.com` alongside engine.js, self-guards to that host). Prefills 图文/文字配图/title/body; **never clicks 发布**. Selectors in `PSEL`.
  - `portal/` — **Content Studio**: a SEPARATE full-page UI for content/trends/publishing/stats. WIRED: trend radar → deep remix (opens+decomposes the source) → publish-prefill (`hs:studio:*`). 养号 stays in the panel; this is the content/publish half.
- Plan is the **brain↔spine contract**: human OR AI emits the same `Plan`; the runner executes it; the governor clamps it.

## Conventions (ALWAYS)

- **Zero-build vanilla JS** (no TS, no bundler, no npm). MV3. Load unpacked from `extension/`.
- **No cloud / no phone-home** except XHS traffic and the operator's own LLM endpoint.
- **The on-page panel is 养号 (engagement) ONLY; publishing/content lives in the separate Content Studio portal (`portal/`).** NEVER add note-posting to the panel — posting during 养号 is a red line (RISK-MODEL: ❌发广告/引流, ❌急于发笔记); it belongs in the deliberate, manual-gated portal.
- **The publisher PREFILLS, never publishes.** `publisher.js` must never have an op that clicks 发布/提交 — it drives 图文→文字配图→title→body and STOPS at the 发布 button; the operator picks ≥3 real topics (from the topic picker, never text-spliced) and clicks 发布 by hand. Honor the frequency门禁 (`publishFreq`: ≤3/24h, ≥30min). Publisher selectors live in `PSEL` (a config fix, like engine's `SEL`); it uses msg type `hs:pub` (engine.js owns `hs:action`).
- **Remix = structure-级复刻, NEVER 文本级抄袭.** To remix, OPEN the source note (build `/explore/<id>?xsec_token=…&xsec_source=pc_feed` from the captured token — a cold deep-URL is sec-gated) and decompose it for real: nethook captures `/feed` (full 正文 + every `image_list` url + `tag_list`) + `/comment/page` (top comments); the LLM emits a `decode` then a NEW note. Never copy a sentence verbatim, never reuse the source's images (cover is 文字配图 or a style-only prompt). Title 8–20 / body ≥80 / ≥3 topics gate (`computePublishGate`).
- **Reading our OWN account = the page's own signed traffic, never our own signed fetch.** `/user/me` is cookie-gated (direct fetch OK); `otherinfo`/`/you/*` are x-s-gated (406) → capture via the MAIN-world interceptor on a page the site itself loads (profile, `/notification`) or the profile DOM. Endpoints/shapes are in `ref/XHS_ALL_IN_ONE` — verify there before changing them.
- **dry-run is the default**; dry-run browses for real but only LOGS the capped mutations. **Comments type-only unless `submit:true`** (no-burn).
- After any code change, validate with `node --check <file>`; keep the engine↔background op contract intact.
- XHS DOM drift = edit `SEL` in `engine.js` (a config fix, not a re-ship).
- **NEVER reinvent an XHS interaction — copy Redaily's EXACT mechanism, then layer our governor/jitter/risk-detection on top (never replacing the pathway).** Before writing any nav/search/engage/gather op, read the live bundle and replicate its selectors + sequence verbatim: `~/Library/Application Support/Google/Chrome/Default/Extensions/abbnjgmnjeidchddihllfjjaogbdommm/3.3.2_0/` (`explore.e52e0709.js`, `static/background/index.js`). Verified facts: nav = open a warmed dedicated `…/explore?_t=Date.now()` popup window (`windows.create` type:popup 1024×768) then `tabs.update` *inside it*; search = type into `#search-input-in-feeds textarea[name="aiSearchTextarea"]` via `execCommand` then verify `location.pathname.includes("search_result")` (NEVER cold-`tabs.update` a deep URL → `/404 error_code=300031` sec gate); like/collect = `.interactions .buttons .like-wrapper`/`.collect-wrapper`, state = `<use> xlink:href === "#liked"/"#collected"`. We must match Redaily on every basic function and only ever do better (anti-detection, governor).
- Orchestrate non-trivial implementation via sub-agents (one concise spec per agent, disjoint files).
- **One plan = one mode** (discovery|comment_section|profile). Redaily is one-type-per-workflow (enforced by its create-factory + `startEngine` switch in `static/background/index.js`). "All 3" = the AI emits a **staggered SET** of single-mode plans into the pool (错峰), never a fused multi-mode session — fusing modes hurts 垂直度 and reads as a bot.
