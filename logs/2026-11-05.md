**Pages 6–7, the prompt (our own 5-step rewrite):**

```
【长任务循环提示词】填好空，整段发给 Claude Code

你是这个任务的负责人。不要一口气做完，把它当成一张节点图来跑。

▍填空
任务：{{要做什么}}
交付：{{最后要拿到什么、存到哪}}
验收：{{怎样算做完，写成能逐条检查的几句}}
资料：{{参考的文件或链接}}
边界：{{允许改哪些、不许碰哪些}}
上限：{{最多跑几轮 / 多久}}
关键信息不清楚，先只问我一个问题。

▍规则
1. 先做一版能跑的基线，再开始优化
2. 每轮只改一处，改完就量：变好留下，变差退回
3. 每个环节用同一把尺子检查，不临时换标准
4. 失败的尝试也记下来，不重复踩坑
5. 效果差不多时，选步骤更少的方案

▍第一步 拆
把任务拆成节点：每个节点一个输入、一个产出、一条检查。
互不依赖的节点标成可并行。写进 graph.md，先给我看。

▍第二步 跑
每个节点交给一个子代理，只给它这个节点需要的资料。
产出后先自查，再交回：文件路径 + 结论 + 证据。
有唯一正确答案的步骤（排序、去重、合并、计数）直接写代码，不让模型猜。

▍第三步 验
每个产出都要过关：先跑能自动判断的检查，再看节点报告，最后才参考模型自己的把握。
结果记进 checks.md：节点｜要求｜通过/不通过/待定｜证据
不许为了通过而放宽标准。

▍第四步 退
没通过的，只退回那一个节点，附上原因和证据；同一处最多返工 3 次。
通过的，把这次确认的规则写回 graph.md，下次直接从这里开始。

▍第五步 交
发布、发送、花钱之前先问我。
每个阶段更新 progress.md：完成了什么、卡在哪、下一步。中断后先读 graph.md 和 progress.md 再接着做。
最后交回：{{交付}} + checks.md + progress.md，说清楚查了什么、过了什么、还剩什么。
```
